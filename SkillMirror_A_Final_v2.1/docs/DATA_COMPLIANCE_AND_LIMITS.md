# 数据来源、合规与系统边界

## 数据清单

| 数据 | 本包来源 | 当前是否真实用户数据 | 用途 |
|---|---|---:|---|
| Skill Mirror 示例 | 团队模拟 | 否 | 选择任务与演示 |
| Challenge/测试 | 团队自建模板或模型候选后验证 | 否 | Python 能力任务 |
| 操作日志/代码版本/Hint | 固定模拟序列 | 否 | 工程闭环验证 |
| 测试结果 | Demo 中实际受限子进程执行 | 否（输入仍为模拟提交） | 验证代码行为 |
| Evidence/Score/Confidence | 上述数据确定性派生 | 否 | 演示能力状态更新 |

本包未包含学生姓名、联系方式、学校、账号凭据或真实学习记录。示例 ID 均为虚构。

## 教育边界

SkillMirror 输出是学习辅助与形成性诊断，不替代教师、学校、考试机构或专业教育服务的最终评价；不得直接用于升学、处分、招聘或其他高影响决策。Score 是当前规则下的任务表现指数，不是正式考试分数或心理测量结果。

## 生产部署要求

- 数据最小化：只采集完成任务所需的代码、测试、提示和必要身份键。
- 明示授权：告知学习者记录内容、目的、保存期限、访问与删除方式。
- 隔离标识：业务用户 ID 与真实身份信息分库/分域管理。
- 访问控制：隐藏测试、参考答案、verified records 仅可信后端可访问。
- 保留与删除：由 B 侧制定可配置期限并支持删除/导出；A 侧算法不要求永久存储。
- 安全：学员代码必须在生产级隔离沙箱执行，禁网络、限 CPU/内存/时间/文件系统。
- 审计：保留算法/规则版本和计算输入摘要；重要变更可回放。
- 未成年人：如面向未成年人，需按适用法律和平台要求取得监护/学校授权并采用更严格最小化策略。

## 模型与风险

LLM 可能产生错题、幻觉、Prompt Injection 响应或泄露答案。当前通过 Schema、锁定字段、executable oracle、Coach 泄题门和 fallback 降低风险，但不能宣称消除所有风险。生产系统应记录模型/Prompt 版本、调用失败和人工申诉入口。

## 模拟结果声明

`examples/full_a_demo_output.json` 与测试报告均为可复现的模拟学习者序列；其中测试执行是真实计算，但不能解释为真实学习者效果、用户满意度或教育提升。对外材料必须保留这一说明。
